审计不会修改存档。正式执行只会移动未保护区块到隔离目录。

地图重置须知流程、保护规则、数据影响与回滚边界

完整流程

  1. 选择服务器并保存保护配置。
  2. 运行只读审计，核对拟刷新区块、容量和车辆数量。
  3. 在游戏内保存并正常停止目标服。
  4. 点击执行并在弹窗中二次确认。
  5. 工具先创建整个存档的 ZIP64 完整备份，并逐文件校验 CRC。
  6. 校验通过后，未保护的地图区块才会移入隔离目录。
  7. 手动启动服务器；发现异常时停服并选择对应备份点完整回滚。

工作原理

工具不清空数据库，只移动未保护的 map/X/Y.bin。每个文件对应一个 8×8 格区块；游戏下次访问缺失区块时按当前地图和 Mod 重新生成。保护区块文件保持原样，所有楼层一起保留。

重置清单会阻止这些区块再次生成原版地图车辆；首次加载后由原版 IsoRegion 工作线程重建墙体、屋顶和室内缓存。

自动保护

保护范围由原版安全屋、全部未死亡角色最后位置、AnimalZone 畜牧区及手动保护矩形组成。边距单位是区块；人物边距设为 0 时，脚下的一个区块仍会保留。

动物存档会全量保留，但畜牧区外的动物数据不保护地图。车辆数据库保留，车辆所在区块当前只统计、不自动保护。

会刷新与会保留

未保护区会重新生成地形、建筑、容器、门窗和世界对象；其中的玩家建筑、落地物、尸体及摆设会消失。人物背包、装备、车辆数据库、全局 Mod 数据和动物数据不会主动删除。

重置区及周围一圈的旧 IsoRegion 缓存会隔离并按需重建；其他区域缓存保持原样。

完整备份

正式执行前会无压缩归档整个多人存档，校验文件数、总字节数及每个 ZIP 条目的 CRC。磁盘空间不足或任何文件校验失败都会取消刷新，不移动地图区块。

完整备份与隔离目录位于目标存档同级目录，正式执行和回滚均不会自动启动游戏服务器。

完整回滚

回滚会再次校验备份，先解压到临时目录，再将当前存档整体改名保留，最后原子替换为刷新前存档。人物、车辆、动物、交易数据和地图会一起回到同一时间点。

刷新后产生的角色进度和世界变化不会合并；它们保存在 *-before-rollback-* 目录，需要人工确认后再清理。

          定点恢复须知流程、保护边界与源头问题
          

            
安全流程
  1. 游戏内保存并正常停服。
  2. 执行全量 CRC 审计。
  3. 核对损坏坐标和安全屋。
  4. 选择损坏前的备份点。
  5. 点击恢复并在弹窗中二次确认。
  6. 启服验证建筑、容器和物品。

            
恢复会做什么
先对当前存档建立完整 ZIP64 快照并逐文件校验，再对备份中的目标区块做 ZIP CRC 与 PZ 内部 CRC 双重校验。仅原子替换指定 map/wx/wy.bin。

            
区域缓存
目标区块及周围一圈 IsoRegion 缓存会失效，相关哈希从 RegionHeader.bin 移除。防护清单只写 R 项，不改变车辆刷新状态。

            
一键回滚
事务保留恢复前的目标区块、RegionHeader、区域缓存和防护清单。停服后可将本次定点恢复完整撤销。

            
为什么会损坏
B42.20.3 原版会先截断正式区块文件再写入，没有临时文件、fsync、写后 CRC 校验和原子替换。写入期间 Java 原生堆崩溃或进程强制终止可留下错误 CRC。

            
当前防护边界
启动闸门能阻止损坏区块被原版自动重生为空白地图，但不能阻止首次写入失败。原子写盘 Agent 需独立测试存档和崩溃注入验证后才能部署。
