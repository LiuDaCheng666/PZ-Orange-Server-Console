# PZ B42 区块灾难恢复

该工具与“选择性地图刷新”完全分开，用于检测和恢复已存在但长度或 CRC 不正确的 B42 `map_X_Y.bin` 区块。

## 恢复流程

1. 停止目标服务器，禁止在 Java 运行时修改存档。
2. 对当前区块执行 B42 内部长度和 CRC 审计。
3. 选择原版 `backups/period` 或 Web 生成的完整存档快照。
4. 恢复前自动创建 ZIP64 完整快照，并逐条读取 ZIP CRC 校验。
5. 对备份中的目标区块再执行 PZ 内部 CRC 校验。
6. 将新区块写入同目录临时文件，`fsync` 后再原子替换正式文件。
7. 隔离目标周围一圈 IsoRegion 缓存，从 `RegionHeader.bin` 移除对应哈希。
8. 只向运行时防护清单写入 `R` 项，不写 `V`，因此不改变车辆刷新状态。
9. 保留本次事务的原区块、RegionHeader、区域缓存和清单，可停服后一键回滚。

Web 可从 `map_meta.bin` 按安全屋持有人或成员名定位，将安全屋矩形和可选外扩转换为区块列表。恢复这些区块会同时恢复其中的普通世界容器及容器物品；人物背包、车辆容器和保存在 Mod 全局数据中的仓库不属于地图区块。

## 为什么会丢失整齐的 8x8 区块

B42.20.3 原版 `IsoChunk.SafeWrite()` 直接打开正式文件、截断为 0 后写入，没有“临时文件 + fsync + CRC 验证 + 原子替换”。若 Java 原生堆崩溃、强制终止或写入过程异常，正式文件会留下错误 CRC。下次启动时原版会放弃该文件并重生初始地图，玩家建筑和容器便会像被整齐挖掉一格。

## 启动 CRC 闸门

启动 CRC 闸门按服务器独立配置且默认关闭。手动开启后，托管启动器在启动 Java 前只检查上次检查后修改的区块。首次启用只建立时间基线，避免旧存档中的历史问题突然阻止全部服务器。发现新损坏时不启动 Java，也不自动选择备份；管理员应在 Web 中核对时间点后恢复。关闭时该闸门不执行，不会影响服务器启动。

## 限制

- 启动闸门可防止“损坏文件被自动重生覆盖”，但不能阻止原版首次写入失败。
- 真正源头防护需要对 `IsoChunk.SafeWrite()` 做原子写盘 Agent。该处于存档核心路径，必须经过独立测试存档、崩溃注入和 Windows 同卷原子移动测试后才能用于正式服。
- 直接运行原始 BAT 会绕过 Web 托管启动器，也会绕过 CRC 闸门。
