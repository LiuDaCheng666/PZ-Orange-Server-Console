# PZ B42 选择性区块刷新工具

用于 B42.20 存档的离线审计和选择性地图区块刷新。

## Web 控制台

登录 `http://127.0.0.1:8790/` 后打开“地图刷新”。Web 页面按服务器分别保存保护配置，
默认安全屋外扩 2 区块、存活人物外扩 8 区块、畜牧区外扩 2 区块，
并可编辑任意数量的手动保护矩形。

1. 保存保护配置。
2. 在“Java 补丁”页启用“选择性地图重置运行时防护”；它只修改下次启动参数。
3. 点击“运行只读审计”，检查拟刷新区块、车辆禁刷区块和区域缓存数量。
4. 正常保存并停止目标游戏服务器。
5. 输入页面显示的 `serverName`，再次确认后正式执行。
6. 等待完整存档 ZIP 写入并通过逐文件 CRC 校验；校验成功后才会隔离区块和旧区域缓存。
7. 检查报告和隔离目录，再从面板手动启动服务器。
8. 如需恢复，停服后选择对应完整备份点并再次输入 `serverName` 回滚。

只有 Web 保留管理员 `admin` 可以保存、审计和执行。正式执行要求最近一次成功审计
与当前配置完全一致，不会自动停止或启动服务器，也不会永久删除区块。

## 为什么不用原版软重置

B42.20.2 仍保留 `-Dsoftreset`，但当前实现只匹配旧文件名
`map_X_Y.bin`。B42.20 实际区块位于 `map\X\Y.bin`，因此软重置会跳过
这些地图区块，无法可靠完成物资刷新。

## 默认保护

- `map_meta.bin` 内的全部原版安全屋（橙子安全屋也使用原版 SafeHouse）
- `map_meta.bin` 内的全部 `AnimalZone` 畜牧划定区
- `players.db` 内全部存活人物的当前位置
- `players.db`、`vehicles.db`、`map_meta.bin`、`global_mod_data.bin`
- `WorldDictionary.bin`、`entity_data.bin`、`map_animals.bin`、`gos_feedingTrough.bin`
- `apop` 和其他派生数据目录

Web 默认安全屋多保护 2 个区块（16 格），人物位置多保护 8 个区块（64 格），
畜牧划区多保护 2 个区块（16 格）。工具会校验、统计、备份并完整保留全局 `apop`
动物数据，但只有 `AnimalZone` 及其外扩范围会保护地图区块。畜牧区外的动物记录不会阻止
地形、建筑、容器或世界对象刷新；这些记录之后可能加载到重新生成的地形中。

## 审计

服务器运行时可以审计，但不能执行：

```powershell
& "<Python安装目录>\python.exe" `
  ".\pz_selective_world_reset.py" `
  --save-root "D:\PZServerData\Saves\Multiplayer\servertest" `
  --server-name "servertest" `
  --report-dir "<面板目录>\reports\selective-world-reset"
```

报告包含安全屋、人物、畜牧划区、仅作信息统计的动物数据文件、车辆、保护区块及拟刷新区块清单。
默认不会修改存档。动物文件或畜牧划区解析失败时，审计与正式执行都会直接失败。

公共商店、公共基地或未申领区域应写入额外保护文件，可参考
`protect-areas.example.json`，并加参数：

```text
--manual-areas .\protect-areas.json
```

## 执行

必须先正常关闭目标服务器，再显式确认：

```text
--apply --confirmation servertest
```

工具不会永久删除区块，而是移动到同级隔离目录。移动前会使用 ZIP64 无压缩归档整个
多人存档，检查归档文件数、总字节数，并读取每个 ZIP 条目验证 CRC。磁盘空间不足、
源文件变化、条目损坏或校验失败时不会开始移动地图区块。

隔离目录同时保留关键数据库、元数据、`apop` 动物数据、被移动的原始地图区块和旧
`isoregiondata` 区域缓存，便于
人工复核。完整备份文件为 `full-save-backup.zip`，校验信息记录在
`full-save-backup-manifest.json`。

工具会在存档根目录生成 `orange-selective-reset-guard-v1.txt`。其中 `V` 记录让运行时
Agent 在每次启动后把相应区块加入原版车辆已生成集合，`R` 记录只在旧区域缓存尚未重建时
触发一次原版 IsoRegion 重算。新的重置会合并已有车辆禁刷记录，不会重新开放旧重置区刷车。

## Web 完整回滚

“地图刷新”页面会列出校验成功的完整备份点。完整回滚要求目标服务器已停止、没有其他
生命周期任务，并要求再次输入完全一致的 `serverName`。

回滚流程会先重新验证归档，然后解压到存档同级的临时目录。解压内容通过数量、容量和
B42 存档结构检查后，当前存档会整体改名为
`<serverName>-before-rollback-<时间戳>`，临时目录再通过同卷目录重命名替换为正式存档。
因此人物、车辆、动物、交易及其他 Mod 数据会和地图一起回到刷新前的同一时间点。
刷新后产生的进度不会合并，但回滚前的当前世界仍完整保留，不会直接删除。

## 影响范围

未保护区块会按当前地图和模组重新生成，包括容器物资、门窗、植被及世界对象。
未保护区域内的玩家建筑、落地物品、尸体和人工摆设也会消失。人物背包和装备保存在
`players.db`，不会随地图区块刷新。车辆保存在 `vehicles.db`，工具不删除车辆数据库，
但报告会列出落在拟刷新区块内的车辆供复核。运行时 Agent 会阻止所有清单区块再次执行
原版 `IsoChunk.AddVehicles()`；橙子车辆商店或其他 Mod 主动创建车辆的接口不受影响。

重置区块及其周围一圈的 `isoregiondata/datachunk_X_Y.bin` 会移入隔离目录，并从
`RegionHeader.bin` 已发现区块索引中同步移除。对应区块首次加载完成后，Agent 调用原版
`IsoRegionWorker` 重建墙体、地板、屋顶和室内连通缓存。其他区域缓存不会删除。
